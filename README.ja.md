# kodachi

[English](https://github.com/yuzujelly2222/kodachi/blob/main/README.md) | 日本語

---
ランダム射影の森を使ったモダンなANNライブラリのPythonネイティブ実装
# これは何か?
---
kodachi は、ランダム射影木の森による近似最近傍探索（ANN）を、NumPy だけに依存する純粋な Python で実装したライブラリです。
最近の ANN では HNSW（階層的航行可能スモールワールド）のようなグラフ型の手法が主流で、速度ではそちらが優れています。一方で、ランダム射影の森は一般にメモリ使用量が少なく、仕組みもシンプルです。
kodachi は速度よりも、C 拡張なしでどこでもすぐ入る手軽さと、コードの読みやすさを重視しています。
---

---

# 使い方
---
```python
import numpy as np
from kodachi import Index

data = np.random.default_rng(0).normal(size=(10000, 64))

index = Index(dim=64, n_trees=20, seed=42)
index.build_index(data)

neighbors = index.search(data[0], k=10)  # コサイン類似度の高い順のデータ番号
```

- `build_index(data)` は形が `(点の数, dim)` の配列を受け取り、木を作ります。もう一度呼ぶと前の木は捨てて作り直します。
- `search(query, k, search_k)` は形が `(dim,)` のクエリに対して、コサイン類似度の高い順に最大 `k` 個のデータ番号を返します。
- データもクエリも内部で長さ 1 に正規化されるので、ベクトルの大きさは結果に影響しません。

---
# パラメータ
---
| パラメータ | デフォルト | 説明 |
|---|---|---|
| `dim` | （必須） | ベクトルの次元数 |
| `n_trees` | `10` | 木の本数。増やすと recall が上がる代わりに、メモリと構築時間が増える |
| `max_leaf_size` | `32` | 1 枚の葉に入る点の最大数 |
| `seed` | `None` | 乱数のシード。固定すると毎回同じ木ができる |
| `k` | `10` | 返す近傍の数 |
| `search_k` | `k * n_trees * 10` | 順位付けの前に集める候補の数。増やすと recall が上がる代わりに遅くなる。データ数以上を指定すると、木を使わず総当たりで正確に計算する |

# 仕組み
---
**木を作る**
1. 点の集合からランダムに 2 点を選び、その 2 点からちょうど等距離にある超平面で空間を 2 つに分けます。
2. 面のちょうど上にある点は、左右にランダムに半分ずつ振り分けます。
3. 点の数が `max_leaf_size` 以下になるまで、左右それぞれで 1〜2 を繰り返します。

これを `n_trees` 回行い、少しずつ違う分け方をした木の森を作ります。データは先に正規化しておくので、ユークリッド距離で分けても順位はコサイン類似度と一致します。

**検索する**
1. 各木でクエリがある側にまっすぐ降りて、葉を 1 枚ずつ集めます。このとき通らなかった側の枝は、優先度付きキューに後回しとして入れておきます。
2. 候補が `search_k` 個たまるまで、後回しにした枝を「クエリが超平面にどれだけ近かったか」の順に探していきます。超平面に近いほど、反対側にも近い点がある可能性が高いからです。
3. 集めた候補とクエリのコサイン類似度をまとめて計算し、上位 `k` 個を返します。

# 計算量と目安
---
`n` を点の数、`d` を次元数、`T` を木の本数とします。

- **構築:** およそ `O(T · n · d · log n)`
- **検索:** 木を降りる部分が `O(T · d · log n)`、候補の順位付けが `O(search_k · d)`
- **メモリ:** データ本体の `n · d` に加えて、木 1 本あたり内部ノードの数（およそ `n / max_leaf_size`）× `d` の法線ベクトル

20,000 点 × 32 次元のランダムなデータでの測定結果（recall@10）は次の通りです。

| n_trees | search_k | recall@10 | ms/クエリ |
|---|---|---|---|
| 10 | 2,000 | 0.76 | 1.7 |
| 20 | 4,000 | 0.95 | 3.5 |
| 50 | 5,000 | 0.98 | 5.0 |
| 総当たり | — | 1.00 | 0.6 |

この規模では NumPy による総当たりのほうが速いことに注意してください。ランダムなデータは近傍探索にとって最も難しいケースで、さらに点の数も少ないためです。木を使う効果が出るのは、点の数が数十万以上で、実際の埋め込みベクトルのように偏りのあるデータです。

**おすすめの決め方:** `n_trees` は 20〜50 くらいから始めて、実際に使うデータで「目標の recall を満たす最小の `search_k`」を測って決めてください。
